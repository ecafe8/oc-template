# 文档编写任务清单

使用规则：

- 未开始：`[ ]`
- 已完成：`[x]`
- 每完成一个文档任务后，直接在本文件勾选。
- 每个任务都包含“目标”和“说明”，方便后续持续推进。

# 文档编写注意事项

1. **目标明确**：每个文档任务都应有清晰的目标，确保编写内容符合预期。
2. **内容详实**：文档内容应详实、准确，避免遗漏重要信息。
3. **格式规范**：遵循统一的文档格式，提升可读性和专业性。
4. **一致性检查**：当编写多个相关文档时，每编写 4-5 个文档后，进行一次整体检查，确保内容的一致性和连贯性。


# 文档写作规范

1. 英文术语首次出现必须附中文说明
2. 所有关系名都要写“英文名 + 中文语义”
3. 所有字段名都要有中文定义
4. 所有章节标题如果偏技术术语，正文第一句必须补中文解释
5. 不允许只写英文不解释，尤其是在 foundation 和 product 文档里
一个例子：
不要写：
- Channel -> has_experience_with -> ProductCategory
建议写：
- 渠道 `Channel` 通过 `has_experience_with（具备某品类内容经验）`关系连接到`产品类目 ProductCategory`。
或者：
- `has_experience_with`：表示某个渠道在一定时间窗口内，持续产出过某产品类目相关内容，或具有该类目的合作经验。
